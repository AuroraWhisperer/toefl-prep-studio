# TOEFL Practice Workbench

## World

The interface treats language as a field of ink on a test sheet. Warm charcoal carries the reading, paper white keeps long passages calm, and a restrained eucalyptus green marks actions and selection throughout the homepage, guide, and workbench. Muted forest and sage give the existing homepage cards depth without changing their layout. The page feels like an instrument for concentrated practice rather than a marketing site.

## Tokens

Styles load through explicit links in `frontend/index.html`. `styles.css` owns shared tokens, typography, controls and shell rules; `landing.css` owns homepage cards; `practice.css` owns the question sheet and shared question material/audio controls used in review; `practice-setup.css` owns practice configuration; `practice-review.css` owns results and material review. Each file keeps its responsive overrides with its owning rules. Mock, adaptive-test and history styles retain their existing files and load after these shared styles. This split preserves the current visual design; it adds no build step.

The homepage, exam guide, setup, practice, results, mock exams, and history inherit these shared roles from `:root` in `frontend/styles.css`:

- Reading / headings: warm charcoal `#303B37`
- Canvas / content: paper `#F7F7F2` / white `#FFFFFF`
- Secondary surfaces: `#EDF0E9`
- Secondary text: `#606D66`
- Primary action / links / selection / focus: eucalyptus `#28675D`
- Primary action hover: deeper eucalyptus `#1D5149`, not black
- Selected surface / supporting audio action: pale sage `#E8F1EC`
- Structural rule / secondary-control border: `#D4DBD3` / `#7D8D84`
- Correct result: olive green `#356343` on `#EDF4E8`
- Incorrect result / recording / destructive action: terracotta `#AA443B` on `#FBEFEC`
- Body: system sans with explicit Microsoft YaHei UI / Microsoft YaHei Chinese fallbacks for controls and reading copy; compact monospace only for question IDs and timers.

Core review text follows a restrained examination style: explanations, expanded audio transcripts, submitted answers, references, and review prompts use `1rem` (16px in ordinary windows, 18px at desktop widths of at least 1600px). Long writing prompts use paragraph markup and regular weight; short question headings use weight 600. Explanations and transcripts use 1.75 line height. Open-response examples and reference points use the normal ink color; objective reference answers and result states retain semantic colors. Writing word counts and timing guidance use 0.8rem sans-serif with tabular numerals. Result notices occupy their own row beneath the heading and score summary so they do not compress the title.

Text uses the full inner width of its page, card, or column and wraps naturally at that boundary. The exam guide, setup help and accent notes, comprehensive-test directions, mock disclaimers and review, compact question prompts, cloze passages, and archive empty states do not add a second character-based width cap. Homepage descriptions also wrap naturally rather than balancing lines. Overall page widths, established task workspaces, inputs, and media keep their own layout constraints. Preserve authored paragraphs, dialogue turns, answer-option separation, and the three learning-explanation lines; do not join them to force a single line. `tests/browser_layout_helpers.cjs` checks rendered content against its actual container across the relevant desktop regressions.

Primary actions use a solid accent; secondary controls use neutral outlines, and return/utility text remains neutral. Audio playback uses a lighter accent surface so it does not compete with navigation. Selection retains native radio marks or explicit checks and does not imply correctness; result labels and recording text preserve non-color cues. Do not introduce per-subject action palettes. Homepage refinements retain the existing layout and decorative frames: the mock ticket uses forest `#405E52` with pale sage copy, while the listening card uses warm charcoal. Their controls use light focus outlines against the dark surfaces. Reading agenda and flyer headers use muted olive `#59624B`; flyers sit on ivory `#F5F6F0`. These material colors do not indicate answer correctness. The guide uses neutral headings, eucalyptus hover and source links, and deeper eucalyptus on link hover.

Color-role guidance follows [Atlassian's color foundations](https://atlassian.design/foundations/color): distinguish neutral, action, selection, and semantic roles rather than color every label. Check rendered text at 4.5:1 and essential control/focus indicators at 3:1, following [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). `tests/browser_palette.test.cjs` covers computed colors, hover/focus, status contrast, shared homepage colors, and desktop scaling.

## Surface

This is a desktop-only product. New work is judged at desktop window sizes and Windows display scaling; existing narrow-window fallbacks remain safeguards, not a separate mobile experience.

The exam guide header places the shared outlined 返回练习首页 button to the left of the title, with both vertically centered in the same row.

The shared task-practice setup uses a compact subject-tab bar followed by a section heading and one bordered white settings sheet. Task types are large radio choices, with a quiet “90 篇” style count badge beside each name, using the same 篇/组/题 unit as its quantity control. The badge's tooltip labels the bank total; it uses secondary text and inherits the action color when selected. Quantity and timing use compact segmented groups with native radio semantics. A ruled footer places the live round quantity/time summary on the left and the primary start action on the right. Listening and Speaking keep the full voice/accent disclaimer in a labeled, initially collapsed disclosure; practice instructions remain a separate disclosure below the sheet. The shared internal color roles and visible keyboard focus are preserved across all four subjects.

The homepage opens with a 36px book mark at the upper left and a compact TOEFL TRAINING wordmark: TOEFL uses a locally hosted Cormorant Garamond semibold italic subset, while TRAINING and all controls retain the sans-serif face. The font license is stored alongside the asset in `frontend/fonts/`; no font service is contacted at runtime. The question-bank total is omitted. Its seven entry cards retain their editorial board: a two-by-two subject grid on the left with a 16px stagger, a forest-green mock-paper ticket above a quiet adaptive-test card on the right, and a horizontal Learning Archive card beneath them. Desktop cards expand with viewport height: gutters grow from 20px to 28px, padding from 24px to 32px, and subject-card minimum heights from 216px to 340px. Headings and descriptions are slightly larger in windows at least 800px tall. The extra space goes into cards and separation rather than a large empty footer, while all seven entries and their actions remain in one desktop viewport, including 1280×720 and the usable browser areas at 125% and 150% display scaling on the target monitor. Short or narrow windows may scroll naturally; content is never clipped to force a fit. Decorative frames use book-cover double rules, a sound-wave edge, manuscript crop marks, a quotation frame, ticket perforations, a dashed reservation frame, and an archive folder tab. Frames do not receive pointer events; narrow-window fallbacks remove the stagger. Paper, warm charcoal, and pale sage preserve the distinction between surfaces.

Card copy describes each subject's distinct tasks without repeating counts or a generic training slogan. The archive leads to a ruled, chronological list rather than nested cards. Its workspace uses the available desktop width with 24–80px side gutters, a compact title and return action, and one white bordered list surface. Category tabs and date filters share a toolbar on wide windows and wrap below 1100px. Each row leads with the practice title, followed by completion time, the original score label, and a review action; a compact total replaces repeated category and per-page counts. The archive omits the repeated English subtitle and introductory explanation. Programmatic heading focus remains available to assistive technology without a decorative outline; interactive controls retain visible keyboard focus. Practice, Mock, and Test tabs separate completed submissions, date filters use local calendar days, and ten-row pages keep large histories navigable. Reopening a record reuses the original answer review; returning preserves its category, dates, and page. Loading, saved-test resume, empty dates, network errors, and recording-upload retry are explicit states.

The homepage separates four subject practice cards on the left from ETS mock papers and the active comprehensive-test entry on the right. The mock-paper picker expands below the cards and lists the five ETS forms; comprehensive tests open their own difficulty setup. Mock papers have their own device check, fixed nine-stage flow, untimed Directions screens, native per-question reading controls and sentence word tiles, forward-only listening and speaking, and final review. These screens use the shared internal color roles. The fixed single-section action is labeled 整科练习 rather than 单科模拟 to avoid confusing it with the five ETS papers.

The practice cards show section names, question counts, task practice and fixed whole-section entry points. The whole card opens task practice through the primary button's extended hit area; the whole-section button has its own hit area and both actions support keyboard navigation. Detailed task descriptions stay in the tabbed setup, which presents 12 task choices across four sections with quantity and timing controls. The practice view puts the title and timer in one compact top bar, followed immediately by the question sheet. Rules, repeated task headings, timing guidance, and skill descriptions are omitted during practice. A single step hides the question rail and previous button; multiple steps retain the rail. Missing-letter inputs sit directly in the passage, and answer progress shares the bottom navigation band with submission. The layout prioritizes fitting the full question and controls in one desktop viewport while allowing long content to scroll. Review groups answers, references, explanations, and time in the left pane and original materials, prompts, and options in the right pane; the panes stack in narrow desktop windows, and missing-letter passages can reveal correct answers. The signature interaction is the text field of the question number: completed items become inked marks in the rail, and the current item is outlined in eucalyptus.

The result view combines its title, score, answered count, and elapsed time into one compact header. Single-group review hides the material navigation. Missing-letter review uses a 33rem answer column (50% wider than the previous 22rem), capped at 45% of the available width in narrower desktop windows. Its answer table uses compact rows with 4px vertical padding, a 2rem number column and 40% for the submitted answer; long entries wrap within their cell, and correct words emphasize only the missing letters. At desktop widths of at least 1100px, the review fills the available viewport below the header and material navigation. The answer table and explanations scroll together in the left pane, with its scrollbar hidden. Vertical wheel gestures anywhere on the visible cloze review page scroll only that left pane, keeping the header and right passage in place; browser zoom gestures retain their native behavior. Wheel input accumulates into one short, frame-synchronized easing motion rather than jumping per tick or restarting an animation for every event. Reversing direction responds from the current position; keyboard input, pointer actions, resizing and changing materials cancel pending motion. Reduced-motion users receive immediate scrolling. The right pane allows keyboard scrolling only when its own content exceeds the available height. Both panes support keyboard scrolling with visible focus. Narrower windows retain natural page scrolling. Expanded explanations use `calc(1rem - 3px)` while retaining 1.75 line height. The passage title is centered on its own row above the right-aligned answer-reveal control, and explanations are collapsed until requested. A Chinese reference translation follows the English passage with a 32px gap, a quiet label and regular body text; it remains visible when the answer-reveal switch changes.

Expanded learning explanations preserve three short text lines: 读懂, 解析, and 下次. Plain Chinese explains the necessary English evidence, with an actionable next-time method rather than another paraphrase of the answer. The existing disclosure uses a compact label and body-sized explanation text, without extra cards or repeated panels. Within a practice or saved review, opening or closing any explanation applies to all questions and remains in effect when switching materials; opening another result or reopening a saved review starts collapsed. Completed mock review labels its learning notes as locally authored rather than ETS explanations.

Every question in submitted and saved review shows its saved difficulty using the practice labels Easy, Medium and Hard in neutral secondary text. Ordinary answers place the difficulty beside the question number; missing-letter review includes a difficulty column for each blank because a passage can contain different levels. Comprehensive-test review uses the same per-question labels, separate from its starting level. Missing difficulty metadata, including ungraded ETS mock items, displays 待分级 rather than inferring a level from the score.

After submission, multiple-choice review navigation uses green for fully correct material groups and red for groups containing a wrong or unanswered question. The active group keeps an inset underline without replacing its result color, and accessible labels and tooltips describe the status. Correct options are green; a selected wrong option is red; other options stay neutral. These states also apply when reopening saved practice history; pre-submission selection uses pale sage and eucalyptus.

Build a Sentence review uses the same green/red navigation states. The right pane fills the sentence frame with the submitted word groups: positions matching the reference have green rectangular backgrounds, while misplaced or unfilled positions have red backgrounds and descriptive labels. Fixed text stays neutral. A server-accepted alternative order is entirely green. The correct sentence appears once in green text underneath; the left pane keeps scores and explanations. Saved sentences that cannot be reconstructed from the archived tiles retain their original text instead of inventing a tile order.

The archive header places the shared outlined 返回首页 button to the left of the title, with the compact 记录管理 disclosure aligned to the right. The disclosure keeps destructive actions separate from date filters and review links. Its actions are 重置概率 and 全部清空, with short descriptions explaining what is retained or deleted. Both use the existing native confirmation pattern; the destructive action is red and names its all-category scope and permanence in the confirmation. Pending actions are disabled, while completion and retryable errors appear above the list. The full-clear action resets the current page and date filters; category selection is retained.

## Motion and states

The comprehensive-test entry is active, with a checklist icon and “选择难度开始” action. Its setup reuses the workbench typography, sage selection and visible keyboard focus: five preset buttons, a labeled native 1–10 select, the linked routing range and one start action. A shared outlined return button with a left arrow sits to the left of the title; the subtitle keeps only the total question count and duration. The setup omits the long routing and question-source explanations below the form. Directions separate untimed instructions from each server-timed stage. Reuse the practice task renderer; show current module and local target level in the title, and lock submitted modules. Completed Test review displays the starting level, two routing outcomes and objective counts; open responses say “待人工复核”, not a fabricated zero score. See [adaptive test behavior](specs/adaptive-tests.md).

An empty Test archive directs the learner to complete the comprehensive test on the homepage; it must not describe the available feature as pending release.

Complete the Words passage review keeps one separate underline per missing letter, matching the practice input spacing. Unfilled positions remain empty underlined slots; switching between submitted and correct answers preserves the slots and the existing correct/incorrect colors.

Reading material titles use centered, bold 1.4rem headings across academic passages, daily-life documents and Complete the Words, including practice, full-section practice, comprehensive tests, saved review and native mock reading. Body paragraphs use a 2em first-line indent, including cloze passages and their Chinese review translations; inline answer slots keep zero indentation. Agenda time rows retain their structured alignment. Complete the Words uses the current passage's title and omits the generic fill-in instruction in original-bank practice.

Complete the Words letter inputs use a 1px underline and a 1px inset focus outline so the active slot stays visible without covering adjacent passage text.

Build a Sentence practice follows the screen example in the ETS overview: context, word bank, then the inline answer frame. The frame has solid underline blanks and immutable fixed words or punctuation; used tiles remain visible but disabled. Empty slots have accessible numbered labels without visible numbers. Click, keyboard, drag, undo and reset preserve individual tile identity. Mock sentence slots retain their separate rendering, exam state and persistence.

Practice uses task-specific layouts rather than a universal two-column template. Listening keeps audio on the left and the question with vertically ordered single-answer options on the right. Daily-life and academic reading use balanced material/question columns; academic passages scroll independently with keyboard access on wide desktops. Complete the Words keeps all ten gaps in the paragraph beneath its passage title. Email places the existing task on the left and the editor on the right. Academic Discussion keeps the professor's question and instructions on the left, with the two existing student posts above the editor on the right; an unrecognized prompt format stays intact instead of losing content. Both writing editors keep the live word count in their header. Build a Sentence follows a vertical flow up to 1100px wide. Speaking centers listening and recording in one primary area, with response transcription in a collapsed practice aid below; saved transcriptions reopen, and microphone failure exposes the manual fallback. Interview questions remain available through the existing collapsed audio script, rather than as a permanent reading prompt. The interface does not fabricate speaker photos, interviewer video, email addresses, or subject lines; recipient and subject text authored in a task is displayed with its instructions. Below 1100px, side-by-side areas stack and passage scrolling returns to the page. See [official task-layout evidence and limitations](docs/ui-task-layouts.md).

Audio controls sit on a light, ruled toolbar rather than a shaded block. Answer options are white, softly rounded rows with boxed letter markers and a reserved selection indicator. Hover uses quiet paper, selection uses pale sage with an explicit eucalyptus check, and keyboard focus has a separate ink outline. These states reuse the existing single-answer behavior; selection does not imply correctness. Recording controls and word counts use spacing rather than nested gray panels.

Reading vocabulary targets use a semantic highlight with pale sage, bold ink, and a eucalyptus underline, preserving the original text. Entering the question positions the independently scrolling passage at the referenced paragraph, keeping the target word visible even in a long paragraph. The page and answer controls retain their position, and answering does not reset manual passage scrolling. Narrow desktop windows retain the existing page-scroll fallback.

Practice and review audio scripts use the full audio-panel width rather than a character-width cap. Each dialogue turn is its own paragraph with a bold speaker label and the existing paragraph spacing; monologues keep their existing line breaks. Scripts remain collapsed during practice and available in review. Listen and Choose a Response omits the repeated learning-aid notice and uses 查看原文 for its disclosure. In submitted and saved review, its Chinese translation follows the English with a 4px gap, aligned to the same left edge in regular body size and secondary text color; both collapse together. Other tasks retain their local learning-aid labels. Replay, scripts, and transcription remain local practice features, not a claim about actual TOEFL controls.

The primary desktop target is 2560×1440, including Windows display scaling. Wide viewports use an 18px base size and a 1760px maximum work area, keeping reading and review in two columns. Question navigation stays at the bottom while scrolling long material. Homepage cards place their two practice actions side by side and use pointer-position tilt capped at 4 degrees on hover-capable mouse devices. Cards settle on exit, navigation, scroll, or focus loss; touch and reduced-motion users receive a static layout.

A question sheet enters with a short upward settle; reduced motion disables it. Audio, recording, loading, empty, error, and submitted states are all visible in text. Focus rings use the action color (or a distinct ink outline on answer options), with a visible outline and offset rather than color alone; controls on dark homepage cards use a light outline.

Question-entry autofocus applies only while that question remains visible and the learner has not already focused another control in its answer area. A delayed paint must not redirect typing to the first field or steal focus after navigation.
